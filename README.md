# BackTunes

Watch YouTube in the background and with the screen off, with ads blocked — on any iPhone, no Mac required, no jailbreak, free.

BackTunes is a small iOS app that plays YouTube's embed player inside a WebView, configures iOS to keep playing audio when the phone is locked, auto-clicks ad "Skip" buttons, and strips ad/tracking domains at the network layer.

## Features

- **Background & screen-off playback** — audio keeps playing when you lock the phone or switch apps. Lock-screen controls (play/pause, ±15 s, scrub, artwork) are wired up too.
- **Ad blocking, two layers** — Safari-style content-blocker rules block ad/tracking domains inside the webview, and a script clicks "Skip" the moment the button appears (short unskippable ads are jumped over).
- **Search** — uses YouTube's own web search endpoint, no API key needed.
- **Library** — bookmarks and play history, stored on-device.
- **No account, no tracking** — the app talks only to youtube.com.

## How it works (the honest version)

iOS suspends web audio when the screen locks — that's true for Safari and every browser on iOS, and no app can change it. So instead of fighting it, BackTunes hosts YouTube's **embed player** inside the app and registers the `audio` background mode. Once the app's audio session is active, iOS treats it like the Music app and keeps it running with the screen off. A looping, near-silent native audio track (inaudible, generated by `Tools/generate_assets.py`) keeps the process alive during long gaps, and a small keep-alive timer nudges the web player every few seconds.

Ads are handled at two levels: the content blocker removes network requests to ad domains, and a 500 ms poller clicks YouTube's skip button. Note YouTube serves ads from the same domains as video sometimes — the skip-click layer catches what the network layer can't.

## Build it (no Mac needed)

The app is compiled on a **free GitHub Actions macOS runner** (public repos get free minutes) and installed on your iPhone with **SideStore**, which re-signs apps *on the phone* — so after initial setup you never need a computer again.

You need:

1. A GitHub account
2. An Apple ID (a free one is fine) — **make sure you have logged in at appleid.apple.com and accepted the latest terms once**, and that two-factor auth is set up
3. Your iPhone, a USB cable, and a Linux PC (only needed once, for setup)

### Step 1 — Push this project to GitHub

```bash
cd backtunes
git init && git add -A
git commit -m "BackTunes initial version"
# create an empty repo named backtunes on github.com, then:
git remote add origin git@github.com:YOURNAME/backtunes.git
git push -u origin main
```

### Step 2 — Build the IPA on GitHub Actions

1. On GitHub, open your repo → **Actions** tab → **Build IPA** → **Run workflow**.
2. Wait ~5–10 minutes for the green check.
3. Download the **BackTunes-ipa** artifact from the run page. Inside is `BackTunes.ipa` — that's your app.

### Step 3 — Set up SideStore on the iPhone

Do this once. Your phone and Linux PC just need to be on the same network for the pairing.

1. Get **JitterbugPair** — it's already bundled in this repo at
   `Tools/jitterbugpair/jitterbugpair` (Linux build), or download it yourself from
   `https://github.com/osy/Jitterbug/releases` (file: `jitterbugpair-linux.zip`).
2. Plug the iPhone in via USB. On the phone, tap **Trust** when asked (the phone must have a passcode set).
3. In a terminal:

   ```bash
   sudo systemctl start usbmuxd        # usually starts automatically on plug
   ./Tools/jitterbugpair/jitterbugpair
   ```

   This prints a **pairing file** like `XXXXXXXX-....-....-.mobiledevicepairing`.
4. **Send that file to the phone** (AirDrop doesn't exist here — use email, Telegram saved-messages, etc.).
5. On the iPhone, in Safari install SideStore from `https://sidestore.io` (tap *Install SideStore*). If iOS refuses to open the page's install link, install the [AltStore PAL-style link resolver](https://sidestore.io/#get-started) shown on that page.
6. Open the **Files** app → find the `.mobiledevicepairing` file → **share → SideStore**. SideStore will ask to install a **VPN profile** — approve it (it's a fake VPN used only to talk to itself; nothing routes through it).
7. In SideStore: **Settings → Sign in with Apple ID** — enter your Apple ID. Free accounts can sign **3 apps** every 7 days.

### Step 4 — Install BackTunes

1. Copy `BackTunes.ipa` onto the phone (same trick: email/Telegram/Files).
2. Open SideStore → **+** → pick the IPA.
3. Wait for "installed". First launch will be blocked by iOS: go to **Settings → General → VPN & Device Management** → trust your Apple ID profile.
4. Open BackTunes. Done. 🎉

### Step 5 — The 7-day ritual (mostly automatic)

Free Apple IDs can only sign apps for **7 days**. SideStore resigns the app **on the phone** over Wi-Fi — just open SideStore every few days and tap the refresh circle next to BackTunes (or enable background refresh in SideStore settings and forget about it). If it expires, nothing is lost: refresh and it launches again.

### Troubleshooting

| Symptom | Fix |
|---|---|
| Build fails on GitHub | Open the failed run; the last 60 lines of xcodebuild output show the error. Most common: Swift typo — copy the error message and fix the file it names. |
| SideStore says "invalid pairing" | Make the pairing file with the phone **unlocked** and re-share it. |
| "Unable to verify app" | Settings → General → VPN & Device Management → Trust developer. |
| Audio stops after ~30 s locked | Lock the screen **while audio is playing**; check Settings → BackTunes → Background App Refresh is on. |
| Ads still show | YouTube changes markup often. Update the selectors in `AdBlocker.swift` — that's the whole fix. |
| Search returns nothing | YouTube occasionally changes its response shape; inspect `YouTubeService.swift` parsing. |

## Project layout

```
project.yml                 XcodeGen definition (generates the Xcode project)
.github/workflows/build.yml CI: macOS runner → unsigned IPA artifact
Tools/generate_assets.py    Generates the app icon + silent keep-alive WAV
BackTunes/
  BackTunesApp.swift        App entry, tabs, persistent player overlay
  PlayerModel.swift         Playback state, lock-screen controls, keep-alive
  PlayerWebView.swift       WKWebView hosting the embed + JS bridge
  AdBlocker.swift           Content-blocker rules + auto-skip script
  YouTubeService.swift      Search via YouTube's Innertube web API
  AudioSessionManager.swift AVAudioSession setup
  LibraryScreen.swift       Bookmarks + history + settings screens
  SearchScreen.swift        Search UI + video rows
  Models.swift              Video model, persisted library
  SettingsStore.swift       Toggles persistence
  Info.plist                Background audio mode, orientations
  Assets.xcassets/          Icon + accent color
  Resources/silence.wav     Generated silent keep-alive loop
```

## Legal note

This project doesn't touch YouTube's private APIs or download media; it embeds the public player like any browser does. Ad blocking is between you and your conscience — it's your phone.

## Building on your own machine later (optional)

Once you own a Mac: install [XcodeGen](https://github.com/yonaskolb/XcodeGen), run `xcodegen generate`, open `BackTunes.xcodeproj`, and press Cmd+R.
